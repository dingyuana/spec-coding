## 7.1 什么是重构？在 Agent 模式下有什么不同？

**重构（Refactoring）** 的定义非常严格：

> 在不改变代码外部行为的前提下，改善其内部结构。

在传统 TDD 中，重构是你自己动手，改几行就跑一次测试，确认全绿再继续。在 Agent 模式下，流程变成了：

```
你审查代码 → 你发现“代码味道” → 你对 Agent 下达重构指令 → Agent 执行 → Agent 运行测试 → 全绿 → 你再次审查
```

**人类负责“识别问题”，Agent 负责“执行修复”。**

| 环节 | 谁来做 | 做什么 |
|------|--------|--------|
| 识别代码味道 | **你** | 用经验和审美判断哪里不好 |
| 下达重构指令 | **你** | 明确告诉 Agent 要改什么 |
| 执行重构 | **Agent** | 修改代码结构，不改行为 |
| 运行测试验证 | **Agent** | 确认 18 个测试仍然全绿 |
| 最终审查 | **你** | 确认改动符合预期 |

## 7.2 人类审查：找出 Agent 代码中的“坏味道”

让我们打开 Agent 在第 5 章写的 `register.py`，用专业的眼光审视它。注意，Agent 写的代码**功能完全正确**，但它可能存在以下问题：

### 坏味道一：`register` 函数做了太多事

```python
def register(email: str, password: str, repo: UserRepository = None) -> dict:
    if repo is None:
        repo = UserRepository()
    
    normalized_email = _validate_email(email)  # 校验邮箱
    _validate_password(password)               # 校验密码
    if repo.exists(normalized_email):           # 查重
        raise ValueError(...)
    user_id = str(uuid.uuid4())                # 生成 ID
    password_hash = _hash_password(password)    # 哈希密码
    repo.save(...)                              # 保存
    return {...}                                # 返回
```

这个函数虽然已经把校验逻辑拆成了 `_validate_email` 和 `_validate_password`，但它仍然“知道太多”。它既管校验、又管生成 ID、又管哈希、又管存储。如果有人想复用“生成 UUID”或者“哈希密码”的逻辑，会发现它们嵌在 `register` 里拿不出来。

### 坏味道二：缺少类型提示的完整性

```python
def register(email: str, password: str, repo: UserRepository = None) -> dict:
```

`repo` 的类型提示是 `UserRepository = None`，但正确的写法应该是 `Optional[UserRepository] = None`。这不是功能问题，但会让 IDE 和类型检查器（如 mypy）报警。

### 坏味道三：docstring 可以更规范

Agent 写的 docstring 已经不错了，但它用的是 Google 风格，而 SystemPrompt.md 里没有明确指定风格。如果你的团队习惯用 NumPy 风格或 Sphinx 风格，就需要统一。

### 坏味道四：缺少模块级别的 `__all__`

`register.py` 是一个会被其他模块导入的文件。目前它暴露了所有函数和类，包括 `_validate_email` 这种私有函数。按照 Python 惯例，应该用 `__all__` 明确声明公开 API。

```python
    """用户注册。
    
    完整流程（按 Spec.md 定义）：
    1. 校验并规范化邮箱（去空格、转小写、检查格式和长度）
    2. 校验密码强度（长度 8-64、至少一个字母和一个数字）

            - PASSWORD_TOO_LONG: 密码长度超过 64
            - WEAK_PASSWORD: 密码不满足字母+数字的组合要求
            - EMAIL_ALREADY_REGISTERED: 邮箱已被注册（不区分大小写）
    
    Example:
        >>> repo = UserRepository()
        >>> result = register("User@Example.com", "SecurePass123", repo)
        >>> print(result)
        {"userId": "a1b2c3d4-...", "email": "user@example.com"}
    """
```

## 7.5 重构后的完整 `register.py`

以下是 Agent 完成三轮重构后的最终版本。你可以对照第 5 章的版本，看看哪些地方变了、哪些地方没变。

```python
# register.py
"""用户注册核心业务逻辑模块。

本模块由 Agent 根据 docs/Spec.md 和 test_register.py 自动生成，
经人类审查后由 Agent 执行重构优化。

公开 API:
    - register: 用户注册核心函数
    - UserRepository: 用户数据仓库
"""

import re
import uuid
from typing import Optional
import bcrypt
from database import get_connection

__all__ = ["register", "UserRepository"]


# ============================================================
# 常量定义（从 Spec.md 提取，重构时未变更）
# ============================================================

EMAIL_MAX_LENGTH = 255
PASSWORD_MIN_LENGTH = 8
PASSWORD_MAX_LENGTH = 64

ERR_INVALID_EMAIL_FORMAT = "INVALID_EMAIL_FORMAT"
ERR_PASSWORD_TOO_SHORT = "PASSWORD_TOO_SHORT"
ERR_PASSWORD_TOO_LONG = "PASSWORD_TOO_LONG"
ERR_WEAK_PASSWORD = "WEAK_PASSWORD"
ERR_EMAIL_ALREADY_REGISTERED = "EMAIL_ALREADY_REGISTERED"


# ============================================================
# 数据仓库层
# ============================================================

class UserRepository:
    """用户数据存储，基于 SQLite 数据库。
    
    负责用户数据的持久化操作。
    """
    
    def exists(self, email: str) -> bool:
        """检查邮箱是否已注册。
        
        Args:
            email: 规范化后的邮箱地址。
            
        Returns:
            bool: 如果邮箱已存在返回 True，否则返回 False。
        """
        conn = get_connection()
        cursor = conn.cursor()
        cursor.execute(
            "SELECT COUNT(*) FROM users WHERE email = ?",
            (email,)
        )
        count = cursor.fetchone()[0]
        conn.close()
        return count > 0
    
    def save(self, email: str, password_hash: str, user_id: str) -> None:
        """保存新用户到数据库。
        
        Args:
            email: 规范化后的邮箱地址。
            password_hash: bcrypt 哈希后的密码字符串。
            user_id: UUID v4 格式的用户唯一标识。
        """
        conn = get_connection()
        cursor = conn.cursor()
        cursor.execute(
            "INSERT INTO users (id, email, password_hash) VALUES (?, ?, ?)",
            (user_id, email, password_hash)
        )
        conn.commit()
        conn.close()


# ============================================================
# 私有辅助函数（以 _ 开头，不在 __all__ 中暴露）
# ============================================================

def _validate_email(email: str) -> str:
    """校验邮箱格式，返回规范化后的邮箱。"""
    normalized = email.strip().lower()
    if "@" not in normalized or len(normalized) > EMAIL_MAX_LENGTH:
        raise ValueError(ERR_INVALID_EMAIL_FORMAT)
    return normalized


def _validate_password(password: str) -> None:
    """校验密码规则，不满足则抛出 ValueError。"""
    if len(password) < PASSWORD_MIN_LENGTH:
        raise ValueError(ERR_PASSWORD_TOO_SHORT)
    if len(password) > PASSWORD_MAX_LENGTH:
        raise ValueError(ERR_PASSWORD_TOO_LONG)
    if not re.search(r"[a-zA-Z]", password):
        raise ValueError(ERR_WEAK_PASSWORD)
    if not re.search(r"[0-9]", password):
        raise ValueError(ERR_WEAK_PASSWORD)


def _hash_password(password: str) -> str:
    """对密码进行 bcrypt 哈希处理。"""
    salt = bcrypt.gensalt()
    hashed = bcrypt.hashpw(password.encode('utf-8'), salt)
    return hashed.decode('utf-8')


# ============================================================
# 公开 API
# ============================================================

def register(email: str, password: str, repo: Optional[UserRepository] = None) -> dict:
    """用户注册。
    
    完整流程（按 Spec.md 定义）：
    1. 校验并规范化邮箱（去空格、转小写、检查格式和长度）
    2. 校验密码强度（长度 8-64、至少一个字母和一个数字）
    3. 检查邮箱是否已被注册（不区分大小写）
    4. 生成 UUID v4 作为用户 ID
    5. 使用 bcrypt 对密码做哈希
    6. 保存用户到数据库
    7. 返回 userId 和 email
    
    Args:
        email: 用户提供的邮箱地址，可包含首尾空格和大写字母。
        password: 用户提供的密码，长度 8-64，需同时包含字母和数字。
        repo: UserRepository 实例，用于数据持久化。
            如果为 None，将创建默认实例。
        
    Returns:
        dict: 包含两个键的字典：
            - userId (str): UUID v4 格式的用户唯一标识
            - email (str): 规范化后的邮箱地址（小写、无首尾空格）
        
    Raises:
        ValueError: 当输入不满足规则时抛出，错误信息为对应的错误码：
            - INVALID_EMAIL_FORMAT: 邮箱格式非法或长度超过 255
            - PASSWORD_TOO_SHORT: 密码长度不足 8
            - PASSWORD_TOO_LONG: 密码长度超过 64
            - WEAK_PASSWORD: 密码不满足字母+数字的组合要求
            - EMAIL_ALREADY_REGISTERED: 邮箱已被注册（不区分大小写）
    
    Example:
        >>> repo = UserRepository()
        >>> result = register("User@Example.com", "SecurePass123", repo)
        >>> print(result)
        {"userId": "a1b2c3d4-...", "email": "user@example.com"}
    """
    if repo is None:
        repo = UserRepository()
    
    normalized_email = _validate_email(email)
    _validate_password(password)
    
    if repo.exists(normalized_email):
        raise ValueError(ERR_EMAIL_ALREADY_REGISTERED)
    
    user_id = str(uuid.uuid4())
    password_hash = _hash_password(password)
    
    repo.save(normalized_email, password_hash, user_id)
    
    return {
        "userId": user_id,
        "email": normalized_email
    }
```

## 7.7 重构的黄金法则（Agent 替你遵守）

| 法则 | 含义 | Agent 如何遵守 |
|------|------|--------------|
| **小步前进** | 每次只改一处 | Agent 每次只执行一条重构指令 |
| **改完就跑测试** | 每次改动后立即验证 | Agent 在每次重构后自动运行 pytest |
| **红灯立刻停** | 测试红了立即回退 | Agent 如果检测到测试失败，会自动回退代码并报告 |
| **不混入新功能** | 重构时只改结构，不加功能 | Agent 严格遵守 Spec.md，不会在重构时“顺手”加东西 |
| **审查后再继续** | 每轮重构后等人类确认 | Agent 完成一轮重构后会暂停，等你审查 |
