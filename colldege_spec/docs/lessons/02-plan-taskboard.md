# PLAN.md：把"做什么"变成"先做什么"

> **场景带入 → 发现问题 → 方案迭代 → 原理拆解 → 效果对比 → 情绪升华**

---

## 一、场景带入：拿到契约后的第一个问题

你刚写好了 7 个 YAML 模块契约，7 个模块、30 个 action。

接下来做什么？先写数据库模型？先写登录？先写路由？

如果直接动手写代码，大概率写了一半才发现——"哦，认证还没做，路由连 token 验证都写不了"。

![](imgs/02/01-plan-taskboard.svg)

## 二、PLAN.md 解决什么问题

PLAN.md 就是**任务看板**——把契约拆成按顺序执行的迭代，每个迭代只做 2-5 个文件。

```
Iter 0: 基础设施（数据库、配置、工具函数）
Iter 1: 认证模块（JWT、密码哈希、依赖注入）
Iter 2: 学生报到（Schema、Service、模型、路由）
Iter 3: 辅导员模块（本班查询、审核、看板）
Iter 4: 管理端模块（全局审核、导出、看板、日志、辅导员管理）
Iter 5: 地图模块（高德 MCP 接入、附近建筑、路线导航）
Iter 6: 集成验证（端到端测试全绿）
```

**每行一个任务，每个任务 2-5 个文件。**

## 三、PLAN 和 SPEC 的关系

| 文件 | 内容 | 什么时候写 |
|------|------|-----------|
| SPEC.md | 全局契约（做什么） | Iter 0 前 |
| specs/*.yaml | 模块契约（接口承诺） | Iter 0 前 |
| PLAN.md | 任务清单（先做什么） | Iter 0 |

**SPEC 回答"做什么"，PLAN 回答"先做什么"。**

## 四、迭代依赖怎么排

不是所有任务都能并行。存在依赖：

```
Iter 0 (数据库/配置)
    ↓
Iter 1 (认证：需要数据库存管理员/辅导员)
    ↓
Iter 2 (学生报到：需要认证 token)
    ↓
Iter 3 (辅导员：需要学生数据)
    ↓
Iter 4 (管理端：需要学生+辅导员数据)
    ↓
Iter 5 (地图：独立，可并行)
    ↓
Iter 6 (验证)
```

**Iter 5（地图）其实是独立的——MCP 客户端不依赖认证。** 但为了教学叙事，放在后面写。

## 五、每个迭代的交付物

```
每个 Iter = 测试文件 + 源码文件
测试文件：tests/unit/test_xxx.py  +  tests/integration/test_xxx.py
源码文件：src/models/ + src/services/ + src/schemas/ + src/main.py 路由
```

**先写测试（RED），再写代码（GREEN），跑测试全绿再进下一个 Iter。**

## 六、效果对比

| 方式 | 写完一个模块的时间 | 改坏概率 | 新人上手 |
|------|------------------|---------|---------|
| 没有 PLAN | 取决于心情 | 高（没边界感） | 翻代码猜 |
| 有 PLAN | 每个 Iter 2 小时 | 低（测试守卫） | 看 PLAN 就知道 |

## 七、情绪升华

PLAN.md 不是一份文档，它是**你和三个月后自己的约定**：

"三个月后我回来看这个系统，打开 PLAN.md 就知道——
这个迭代做了认证，那个迭代做了管理端，测试在哪里，路由在哪里。"

**没有 PLAN，系统是一团代码。有 PLAN，系统是 6 个有序的故事。**
