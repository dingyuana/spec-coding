> 版本：2.0 — 新增辅导员角色、扩展报到字段、高德 MCP、操作日志
> 所有需求需可追溯至 SPEC.md（v2.0）和 specs/*.yaml 中的验收标准。

## 一、项目背景

### 1.1 现状痛点

大学新生报到日，传统流程存在以下问题：

| 问题 | 影响 |
|------|------|
| 线下纸质表格填写 | 信息易丢失、易涂改，事后录入工作量大 |
| 报到信息字段不全 | 缺少身份证、紧急联系人、体检等关键字段 |
| 报到状态不透明 | 学生不知道自己的信息是否被审核通过 |
| 辅导员只能查全校 | 辅导员看不到本班学生的具体报到情况 |
| 管理员统计困难 | 各学院/各班级报到人数需手动汇总 |
| 校园陌生难导航 | 新生找不到食堂、教学楼、宿舍楼 |
| 信息重复提交 | 同一学生多次填写，无法识别 |
| 审核操作无记录 | 谁审核了、什么时候、结果如何，无迹可查 |

### 1.2 目标

通过数字化报到系统，实现：
- 学生手机端自助填写完整报到信息（含扩展字段）
- 辅导员 Web 端查看**本班**学生报到状况、审核本班
- 管理员 Web 端全局审核、导出、看板、操作日志、辅导员管理
- 校园地图导航（高德 MCP）辅助新生快速熟悉环境
- 报到数据自动汇总，消除人工统计

## 四、业务流程

### 4.1 学生报到流程

```
打开微信小程序
    ↓
微信授权登录（获取 openid + session_key）
    ↓
填写完整报到信息（14 个字段）
    ↓
提交（状态：PENDING → SUBMITTED）
    ↓
等待审核（辅导员优先 / 管理员兜底）
    ↓
审核结果
    ├── 通过 → 状态 APPROVED，报到完成
    └── 驳回 → 状态 REJECTED，填写原因 → 学生可修改重新提交
```

### 4.2 辅导员审核流程

```
辅导员登录 Web 端面
    ↓
自动过滤：只显示 class_name = 本人负责班级的学生
    ↓
查看本班列表（支持状态筛选）
    ↓
逐条审核
    ├── 通过 → 状态 APPROVED → 记录到 AuditLog
    └── 驳回 → 填写原因 → 状态 REJECTED → 记录到 AuditLog
    ↓
（可选）查看本班看板
```

### 4.3 管理员审核流程

```
管理员登录 Web 端面
    ↓
查看全局报到列表（学院/班级/状态筛选）
    ↓
逐条审核
    ├── 通过 → 状态 APPROVED → 记录到 AuditLog
    └── 驳回 → 填写原因 → 状态 REJECTED → 记录到 AuditLog
    ↓
（可选）导出 CSV
    ↓
（可选）查看操作日志 / 全局看板 / 管理辅导员
```

### 4.4 地图导航流程

```
学生 / 辅导员 / 管理员 打开地图功能
    ↓
获取当前位置（小程序自动定位）或手动选择起点
    ↓
选择目标建筑（附近建筑列表 / 建筑类型筛选）
    ↓
调用高德 MCP 服务计算完整步行路线
    ↓
展示路线：坐标点 + 距离 + 步行时间 + 中文指引
    ↓
MCP 不可用 → 降级为静态校园数据 + 日志警告
```

## 五、非功能需求

| ID | 类型 | 需求 | 验收标准 |
|----|------|------|---------|
| NFR-01 | 性能 | API 响应时间 < 200ms | 集成测试断言 |
| NFR-02 | 安全 | 密码 bcrypt 加密存储（管理员 + 辅导员） | 代码审查确认 |
| NFR-03 | 安全 | 微信 session_key 不落库 | 代码审查确认 |
| NFR-04 | 安全 | 密钥从 .env 读取，不入 Git | .gitignore 确认 |
| NFR-05 | 安全 | 无效 token 返回 401 | 测试用例覆盖 |
| NFR-06 | 安全 | 辅导员无法访问非本班学生数据 | COUN-S5 测试通过 |
| NFR-07 | 安全 | 学生只能查看/修改自己的数据 | STU-S5 测试通过 |
| NFR-08 | 安全 | 身份证号不在响应中明文返回给他人 | 测试用例覆盖 |
| NFR-09 | 可用性 | MCP 不可用时不崩溃，降级返回静态数据 | MCP-S5 测试通过 |
| NFR-10 | 可维护性 | 测试覆盖率 ≥ 80% | pytest-cov 验证 |
| NFR-11 | 一致性 | 管理员/辅导员不存在和密码错误的消息相同 | AUTH-S5, AUTH-S7 |
| NFR-12 | 审计 | 所有审核操作记录到 AuditLog | ADM-S3, ADM-S4 |

## 六、数据需求

### 6.1 实体关系

```
Student（报到记录）
├── id (PK)
├── openid (unique)
├── student_id (unique)
├── name
├── college
├── class_name        ← 新增：班级
├── building
├── phone
├── id_number         ← 新增：身份证号
├── emergency_contact ← 新增：紧急联系人
├── emergency_phone   ← 新增：紧急联系电话
├── health_info       ← 新增：体检信息
├── enrollment_date   ← 新增：入学日期
├── status (enum)
├── reject_reason
├── created_at
└── updated_at

Counselor（辅导员）
├── id (PK)
├── username (unique)
├── password_hash
├── role (counselor)
├── name
├── college
├── class_name        ← 负责班级
└── created_at

Admin（管理员）
├── id (PK)
├── username (unique)
├── password_hash
├── role (admin)
└── created_at

AuditLog（操作日志）
├── id (PK)
├── actor_id
├── actor_type (admin/counselor)
├── action (approve/reject/export/view)
├── target_id
├── target_type
├── detail
├── ip_address
└── created_at
```

### 6.2 状态流转

```
PENDING → SUBMITTED → APPROVED
                ↘ REJECTED →（修改后）→ SUBMITTED
```

## 七、Non-goals（明确不做）

| 不做 | 原因 |
|------|------|
| 学生账号注册 | 直接使用微信授权，无需注册 |
| 短信通知 | 使用微信小程序模板消息（另行讨论） |
| 宿舍自动分配 | 由学生手动选择宿舍楼栋 |
| 实时聊天 | 不在本次范围 |
| 多学校配置 | 单校使用 |
| 真实高德 MCP 连接 | 使用 mock 模式实现核心逻辑，真实连接后续配置 |
| 辅导员导出 CSV | 仅管理员可导出 |
| 辅导员查看操作日志 | 仅管理员可查看 |
