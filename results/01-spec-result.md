## 📄 我们写出来的文件

打开 `user-login/SPEC.md`，这是我们**第一个**产出的文件。在写任何代码之前，它已经把"要做什么"说清楚了。

### 核心内容摘要

**接口：** 只有 1 个，但写了 3 种返回情况

```
正常 → { "token": "..." }
异常 → { "error": "用户名或密码错误" }
参数错 → { "error": "用户名和密码不能为空" }
```

**数据模型：** User 表只有 4 个字段（最简设计）

| 字段 | 类型 | 作用 |
|------|------|------|
| id | number | 用户 ID |
| username | string | 登录名 |
| passwordHash | string | bcrypt 加密后的密码（不是明文！） |
| createdAt | Date | 注册时间 |

**JWT Token 里面长这样：**

```json
{ "user_id": 1, "exp": 1747353600 }
```

> `user_id` 是用户 ID，`exp` 是过期时间戳。24 小时后 token 失效。

**验收标准：** 4 个 Scenario，每个都写清楚了"输入什么 → 输出什么"

### 为什么要先写这个？

没有 SPEC 时的开发流程：

```
产品说"做个登录" → 你直接写代码 → 写完不知道对不对 → 手动测两下 → 上线
```

有 SPEC 时的开发流程：

```
产品说"做个登录" → 先写 SPEC → 前端后端一起看 → 达成共识 → 写代码 → 测试验证
```

**SPEC 是团队的地图，不是个人的笔记。**
